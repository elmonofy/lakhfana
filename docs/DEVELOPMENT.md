# Lakhfana — Developer Guide

Lakhfana re-types selected text as if the same physical keys had been pressed in the other keyboard layout
(e.g. `hgsghl ugd;l` → `السلام عليكم`). There are two native apps that share one algorithm:

| | Windows | macOS |
|---|---|---|
| Language / UI | C# 5, WinForms, .NET Framework 4.8 | Swift 5 mode, AppKit + SwiftUI, macOS 13+ |
| Build | `build.ps1` with the in-box `csc.exe` (no SDK) | Swift package, `mac/scripts/bundle.sh` |
| Output | single `Lakhfana.exe` (self-installing) | `Lakhfana.app` in `Lakhfana.dmg` (universal) |
| Hotkey | `RegisterHotKey` | Carbon `RegisterEventHotKey` |
| Key maps | `ToUnicodeEx` | `UCKeyTranslate` on `kTISPropertyUnicodeKeyLayoutData` |
| Copy / paste | `SendInput` Ctrl+C / Ctrl+V | `CGEvent` ⌘C / ⌘V (needs Accessibility) |
| Switch layout | `WM_INPUTLANGCHANGEREQUEST` | `TISSelectInputSource` |

Design notes with the original contracts: [design.md](design.md) (Windows) and [mac-design.md](mac-design.md).

## How a conversion works

1. **Hotkey fires.** A normal shortcut uses `RegisterHotKey`. A modifier-only shortcut on Windows (e.g. Ctrl + Shift,
   two or more modifiers, no other key) uses low-level keyboard/mouse hooks (`src/App/ModifierChord.cs`): it fires
   on release only if exactly that set was held, nothing else was pressed or clicked, and the chord lasted under
   1.2 s; injected input is ignored. The combination Windows uses to switch input language (`HKCU\Keyboard Layout\Toggle`,
   default Alt + Shift) is rejected.
   Then: If Alt/Win (Windows) is held, a dummy key is tapped so releasing it doesn't open menus.
   A worker waits until the user releases all modifiers.
2. **Guard checks.** Skip our own windows; refuse password fields (macOS checks the focused element via AX);
   on Windows refuse elevated targets (UIPI would drop our input) with a message.
3. **Back up the clipboard** (every readable format/type).
4. **Copy.** Send Ctrl+C / ⌘C and wait for the clipboard sequence number / `changeCount` to move.
   Editor "empty selection copies the whole line" results (VS Code, Visual Studio) count as *no selection*.
5. **No selection → select the line** (Home, Shift+End / ⌘←, ⌘⇧→) and copy again — on macOS only when the
   focused element is editable text, so browsers don't go Back and terminals don't switch tabs.
6. **Convert** (below). Pressing the hotkey again on exactly the text we just pasted returns the original.
7. **Paste.** Write the result marked as excluded from clipboard history / managers, send Ctrl+V / ⌘V,
   switch the keyboard layout, wait for the paste to land, then restore the original clipboard — unless
   something else changed the clipboard meanwhile.

## The converter

- **Key maps.** For each layout, every printable key is translated unshifted and shifted with the OS API.
  Outputs may be several characters (Arabic 101 / Arabic-PC: `B` → `لا`). A reverse map (text → key)
  prefers unshifted keys. Dead keys, control characters and function-key code points are skipped.
- **Direction per word.** Text is split into whitespace / non-whitespace runs (whitespace is copied exactly).
  Each word counts characters that only layout A types vs. only layout B types; the majority decides.
  Undecided words use the whole-text majority, then the window's current layout.
- **Lam-alef ambiguity.** `لا` can be one key (`b`) or two (`g`+`h`). When the target layout is Latin and a
  word can be segmented several ways, every segmentation (capped at 256) is scored with an English
  letter-bigram model (`EnglishScorer`: mean log-probability, start/end-of-word terms, penalty for a capital
  after a small letter) and the best one wins: `مهلاف` → `light`, `شلاخعف` → `about`, `لأخخي` → `Good`.
- **Pass-through.** Characters that no key of the source layout types (emoji, digits shared by both…) are
  left unchanged. On macOS the converter works on Unicode scalars so Arabic diacritics are never merged into
  grapheme clusters.

## Windows

### Build and test

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1 -Test
```

Produces `dist\Lakhfana.exe`, `dist\tests\ConverterTests.exe` (run with `-Test`) and
`dist\tests\UiSnapshot.exe` (writes `dist\snapshots\*.png` — look at them after any UI change).

Constraints (the in-box compiler is C# 5): no `$"…"`, `?.`, `nameof`, expression-bodied members,
auto-property initializers, `out var`, tuples or pattern matching. Sources are UTF-8 with BOM and compiled
with `/codepage:65001` (they contain Arabic strings).

The converter tests use the installed en-US (0409) and Arabic 101 (0401) layouts; they look for an installed
HKL first and only `LoadKeyboardLayout` (then unload) when missing, so they don't leave a ghost layout behind.

### Running without installing

`dist\Lakhfana.exe /portable` skips the install flow (handy for testing). `/uninstall` (optionally with
`/quiet`) removes the installed copy. Launching the app while it is already running opens its Settings.

### Install, update, uninstall

Running the downloaded exe shows onboarding, then copies itself to `%LOCALAPPDATA%\Programs\Lakhfana`,
creates a Start-menu shortcut, writes the HKCU uninstall entry (publisher and links come from
`src/UI/Credit.cs`) and the Run key. Running a **newer** exe while installed updates in place; the same
version just opens Settings; an older one asks before downgrading. Settings and `error.log` live in
`%APPDATA%\Lakhfana`.

## macOS

```bash
cd mac && swift test              # converter tests (uses installed Arabic / Arabic-PC / US layouts)
bash mac/scripts/bundle.sh        # → mac/dist/Lakhfana.app and mac/dist/Lakhfana.dmg
```

A universal build needs Xcode; with only the Command Line Tools use `LAKHFANA_ARCHS=arm64`.
Resources (Info.plist, `ar.lproj`, icon) are copied by the script — don't use SwiftPM `resources:` /
`Bundle.module`. The app is ad-hoc signed, so macOS may ask for the Accessibility permission again after an
update; a Developer ID + notarization would remove that and the Gatekeeper step without code changes.

## CI and releases

`.github/workflows/build.yml` runs on every push:

- **macOS (macos-15):** `swift test`, `bundle.sh`, mounts the dmg and verifies the signature, launches the
  app as a smoke test, uploads `Lakhfana-dmg`.
- **Windows (windows-latest):** `build.ps1 -Test`, uploads `Lakhfana-exe`.

To release:

1. Bump the version in `src/AssemblyInfo.cs` (Windows) and `mac/Resources/Info.plist` (macOS; CI also
   overrides it from the tag).
2. Commit, then tag and push: `git tag -a v1.2.3 -m "لخفنه 1.2.3" && git push origin v1.2.3`.
3. The release job attaches `Lakhfana.dmg` and `Lakhfana.exe` to the GitHub Release. The links
   `releases/latest/download/Lakhfana.exe` and `…/Lakhfana.dmg` always point at the newest release.

## Known limitations

- Neither app is code-signed by a trusted certificate yet (SmartScreen on Windows, Gatekeeper on macOS).
- Windows can't type into apps running as Administrator unless Lakhfana also runs elevated (UIPI).
- Only unshifted and Shift layers are mapped (no AltGr / Option layer).
